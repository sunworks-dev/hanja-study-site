# 앱의 획순·채점 체험 재사용

## Decision
정적 소개 사이트에 앱의 明·木 획순 JSON·GlyphFit 변환과 StrokeScorer를 포팅한다. Flutter 런타임·사용자 DB·FSRS를 로드하지 않는다. 기본은 明 따라 쓰기이고 조합 체험에서도 바로 이어진다.

## Drivers
사용자가 앱의 한자 그리기 기능을 소개 사이트에 최대한 적용하도록 요청했다. 기존 기능은 木 글꼴 위 채점 없는 캔버스였다. 최초 방문에서 설치 없이 실제 획 모양·방향·재시도·기억 쓰기를 경험해야 한다.

## Alternatives
- Flutter iframe: 실제 위젯 재사용은 가장 높지만 전체 부팅·온보딩·저장소·접근 제어와 작은 화면 스크롤까지 함께 들어온다.
- 별도 Hanzi Writer 라이브러리: 작은 체험은 쉽지만 앱과 채점 기준이 달라진다.
- 데이터·채점 포팅(채택): 사이트 구조를 유지하면서 실제 앱과 수치 비교가 가능하다.

## Why
순수 채점은 작은 함수이며 앱 데이터도 두 글자 약 4.3KB다. 실행한 Dart 결과 60개를 fixture로 저장해 웹 결과·좌표 변환과 대조했다. 손글씨 평가 모델과 변환 값의 일치가 핵심이며 DOM UI 자체는 사이트에 맞춘다.

## Consequences
앱 변경 시 포팅 코드도 갱신해야 한다. `tests/writing.test.mjs`가 채점 기준을 고정한다. 세 번 실패한 획은 자동으로 진행하지만 성공으로 세지 않는다. 평균 정확도에는 도움 받은 획의 마지막 결과도 포함한다. 소개 기록은 메모리에만 존재하며 새로고침하면 사라진다.

## Follow-ups
앱 채점·자산 변경 시 fixture와 좌표를 재추출한다. 실제 iOS Safari/Android 기기 확인, 공개 배포, 도메인 HTTPS 인증서 정정은 이번 로컬 구현·Phi 검증과 별개다.
